# 🚀 Инженерный Роадмап: Из PHP/Symfony в Go Highload & Systems

- **Цель:** Стать уверенным системным инженером и пройти собеседования в тех-топы (Яндекс, Авито, Ozon, Т-Банк).
- **Интенсивность:** ~15 часов в неделю.
- **Срок:** 9–12 месяцев.
- **Главный принцип:** Минимум фреймворков, максимум стандартной библиотеки (`stdlib`), системных вызовов ОС и ручного управления памятью.

---

## 📅 Блок 1. Основы языка и Управление памятью (Месяцы 1–2)

**Цель:** Понять синтаксис Go, научиться мыслить указателями и типами данных, разобраться, как компилятор распределяет память.

### 📚 Теория для изучения

- [ ] Компиляция (`go build`), кросс-компиляция (`GOOS`, `GOARCH`), работа Go Modules (`go.mod`).
- [ ] Строгая типизация, устройство слайсов (`slices`) и мап (`maps`) изнутри как структур данных.
- [ ] Указатели (`*`, `&`). Отличие передачи данных по значению от передачи по ссылке.
- [ ] **Стек (Stack) против Кучи (Heap)**. Механизм **Escape Analysis** (Анализ побега переменных).
- [ ] Устройство сборщика мусора Go (Garbage Collector: алгоритм Трёхцветной разметки / Tri-color mark and sweep).



### ⚙️ Практический проект

- **Собственная библиотека сериализации и работы с бинарными данными.**
  - *Суть:* Написать код, который берет сложную структуру данных, превращает её в кастомный поток байт (`[]byte`) и умеет читать обратно. 
  - *Инженерный вызов:* Научиться выделять память под слайсы ровно в байтах, без лишних аллокаций в куче.



### 🛠️ Инструменты

- [ ] Команда `go test -bench` и `go test -benchmem` для замера скорости и аллокаций памяти.
- [ ] Флаг компилятора `go build -gcflags="-m"` для слежки за Escape Analysis.

---



## 📅 Блок 2. Concurrency: Многопоточность и Железо (Месяцы 3–4)

**Цель:** Полностью освоить конкурентность Go, заставить ядра процессора работать параллельно, научиться синхронизировать память.

### 📚 Теория для изучения

- [ ] Планировщик Go (**GMP-модель**: Goroutine, Machine, Processor). Как Go размазывает горутины по ядрам ОС.
- [ ] Переключение контекста (Context Switch) в процессах ОС против переключения горутин в Go.
- [ ] Каналы (`chan`), буферизированные и небуферизированные. Анатомия каналов (структура `hchan` под капотом).
- [ ] Синхронизация: `sync.Mutex`, `sync.RWMutex`, `sync.WaitGroup`, `sync.Map`.
- [ ] Состояние гонки (**Race Condition**) и способы его поиска.
- [ ] Продвинутый уровень: Атомарные операции (`sync/atomic`), концепция **Lock-Free** структур данных.



### ⚙️ Практический проект

- **Высокопроизводительный In-Memory Cache (Аналог Redis) + Worker Pool.**
  - *Суть:* Хранилище «ключ-значение» в оперативной памяти, которое безопасно держит конкурентную нагрузку в 10 000+ горутин. Должен быть фоновый воркер очистки просроченных ключей по TTL.
  - *Этап усложнения:* Переписать критические узлы (счетчики, блокировки) с мьютексов на атомики (`sync/atomic`), замерить бенчмарками прирост производительности.



### 🛠️ Инструменты

- [ ] Запуск кода с флагом детектора гонок `go run -race`.
- [ ] Встроенный профилировщик `pprof` для поиска взаимных блокировок (deadlocks) и утечек горутин.

## 📅 Блок 3. Системное программирование, Сети и ОС (Месяцы 5–6)

**Цель:** Спуститься на уровень операционной системы Linux/macOS. Понять, как работают сокеты, файлы и процессы.

### 📚 Теория для изучения

- [ ] Как ОС работает с сетью. Модель OSI, TCP/IP, устройство сетевых сокетов.
- [ ] Блокирующий ввод-вывод (Blocking I/O) против неблокирующего (Non-blocking I/O).
- [ ] Системные вызовы ядра ОС (`syscall`). Как работает сетевой поллер Go (`netpoller`) поверх **Epoll** (Linux) / **Kqueue** (macOS).
- [ ] Жизненный цикл процессов в ОС. Потоки ввода-вывода (`stdin`, `stdout`, `stderr`) и их перенаправление.



### ⚙️ Практический проект

- **Свой FastCGI / CGI-сервер (Аналог PHP-FPM) на чистых системных вызовах.**
  - *Суть:* Написать HTTP-сервер, используя только пакет `net` (или `syscall`). Сервер принимает веб-запрос, через пакет `os/exec` запускает реальный PHP-скрипт на вашем компьютере, передает ему заголовки через поток ввода `stdin`, забирает ответ из потока `stdout` и возвращает клиенту.

## 📅 Блок 4. Архитектура Хранения Данных (Месяцы 7–8)

**Цель:** Понять, как устроены базы данных на физическом уровне (жесткий диск, SSD, файловая система).

### 📚 Теория для изучения

- [ ] Устройство движков хранения (Storage Engines) в современных СУБД.
- [ ] Архитектура **WAL (Write-Ahead Log)** — дозапись в конец файла для обеспечения надежности данных.
- [ ] Разница между случайным доступом к диску (Random I/O) и последовательным (Sequential I/O).
- [ ] Архитектура **LSM-Tree** (Log-Structured Merge-tree) против **B-Tree** (почему RocksDB быстрая на запись, а Postgres — на чтение).



### ⚙️ Практический проект

- **Собственная дисковая база данных (Архитектура Bitcask/LSM).**
  - *Суть:* Написать движок, который сохраняет данные на диск. Запись идет строго в конец WAL-файла. В памяти держится индекс (ключ -> смещение в байтах `offset`). При чтении программа делает `Seek` по файлу и выдергивает значение. Реализовать фоновый процесс слияния файлов (Compaction/Merge) для очистки старых данных.

## 📅 Блок 5. Алгоритмы, System Design и Подготовка к Топам (Месяцы 9–12)

**Цель:** Переключиться на прохождение жестких секций в Яндекс/Авито/Ozon. Набить руку на алгоритмах и масштабировании инфраструктуры.

### 🧠 Направление А: Алгоритмы (Параллельно всему блоку)

- [ ] Выделять по 3-4 часа в неделю на **LeetCode**.
- [ ] Решить **70–100 задач** (уровни Easy и Medium) строго на Go.
- [ ] *Фокус на темах:* Слайсы, Мапы, Два указателя, Скользящее окно, Бинарный поиск, Деревья, Хэш-таблицы.



### 🏗️ Направление Б: System Design (Проектирование систем)

- [ ] Изучение паттернов Highload: Шардирование, Репликация, Консистентное хэширование, Очереди сообщений (Kafka/RabbitMQ).
- [ ] Чтение книги Мартина Клеппманна *«Высоконагруженные приложения»*.
- [ ] Разбор типовых кейсов: «Как спроектировать аналог YouTube», «Как спроектировать счетчик лайков на миллионы пользователей».



### 💼 Направление В: Боевой коммерческий Go (Последние 2–3 недели)

- [ ] Изучить стандартные паттерны микросервисов в Go: пакет `net/http`, работу с базой через драйвер `pgx`.
- [ ] Понять подходы к структурированию папок в Go (Clean Architecture / Layered Architecture).
